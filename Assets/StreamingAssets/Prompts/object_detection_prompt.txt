================================================================================
FEATURE PAYLOAD: OPEN-VOCABULARY OBJECT DETECTION & MASK ATLAS SPECIFICATIONS
================================================================================
You are processing a request that targets real-time computer vision data. An
open-vocabulary detector (no fixed class list) runs in parallel and returns, per
frame, the bounding boxes and segmentation masks of the objects YOU declare for
this shader. You are REQUIRED to (A) declare the target objects in a header block,
and (B) implement the buffer layout, coordinate checks and lookups below.

0. TARGET CLASS DECLARATION (MANDATORY when the request needs object targeting):
At the very top of the shader file, BEFORE the `Shader "..."` line, emit a header block
of TWO REQUIRED LINES plus an optional third. Never emit @detect-classes without
@detect-coco directly beneath it — they are one block, not two independent options:

    // @detect-classes: <natural-language phrases, in slot order>   REQUIRED
    // @detect-coco:    <one COCO class per phrase, same order>     REQUIRED
    // @detect-confidence: 0.3                                      optional

Worked example — note that the third phrase has no COCO equivalent and therefore gets
`-`, and that the line is still emitted:

    // @detect-classes: person, red coffee mug, guitar
    // @detect-coco:    person, cup,            -
    // @detect-confidence: 0.3

The FIRST line is the vocabulary for the open-vocabulary detector, which can find
anything you name — you do NOT need any predefined dataset for it. The SECOND line
exists because the app can also run a faster detector that only knows 80 fixed COCO
classes and cannot be told what to look for. You translate the list for it here, once.

Rules for @detect-classes:
- The ZERO-BASED POSITION of each phrase is its `labelID` slot:
  slot 0 = "person", slot 1 = "red coffee mug", slot 2 = "guitar".
- In the shader you filter by these slot indices, NEVER by any external dataset id.
- List only what the user actually wants highlighted/affected. Keep phrases short
  and visual ("red coffee mug", not "the mug I drink coffee from in the morning").
  Use the plain category name and add a qualifier only to tell objects apart: every
  extra word makes a complete miss more likely ("computer monitor" finds nothing where
  "tv" finds the same screen), and the @detect-coco name is searched for as well.
- Name WHOLE OBJECTS, never parts of objects. See the section below — this is the
  single most common way a shader ends up detecting nothing.
- `@detect-confidence` is optional (default 0.25); lower it for hard/rare objects.
- If the request is a pure visual effect that needs NO object targeting, omit BOTH
  @detect-classes and @detect-coco — then no detection runs at all.

WHOLE OBJECTS ONLY — how to handle a request about a PART:
The detector finds objects, not their parts. It proposes regions the way an object
detector does and then matches your phrase against them, so a phrase naming a part
("face", "head", "hand", "car wheel", "laptop screen", "shirt") matches nothing at
all: there is no proposal for it, and you get an empty result rather than a rough one.

So translate a part request into: DETECT the containing object, then RESTRICT the
effect geometrically inside the shader. The bounding box gives you everything you
need — `det.boundingBox.xy` is the viewport-space center, `.zw` the size (z = width,
w = height), and viewport y INCREASES UPWARD, so the top of an object is the high-y
end of its box. The client already flips the detector's image-space y for you, so this
always holds: do not add a compensating flip of your own.

Request: "pixelate all faces"
    // @detect-classes: person
    // @detect-coco: person
    // @detect-note: faces are a part, so this targets `person` and affects the
    //               upper ~30% of each box, which is where the head is.

    // inside the per-detection block, after the existing bounds check:
    float boxTop    = det.boundingBox.y + det.boundingBox.w * 0.5;
    float headBand  = det.boundingBox.w * 0.30;   // upper 30% of the person box
    if (i.uv.y > boxTop - headBand) {
        // pixelate here
    }

Apply the same move to any part: "car wheels" -> detect `car`, affect the lower band;
"laptop screen" -> detect `laptop`, affect the upper band. Choose the band from where
the part actually sits, and prefer covering slightly too much over too little.

A band is enough for effects that change pixels in place (blur, pixelate, tint, outline).
Effects that MOVE pixels (flip, rotate, mirror, swap, swirl, zoom) also need the part's
own center as the pivot: flipping a 30% band of a standing person turns the chest into the
head and puts the face on the chest. For a head, use a square at the TOP of the person box,
centered horizontally, with side = min(0.6 * box width, box height) for both its width and
height (the shoulders set the box width, so this holds for standing, sitting and cropped
people alike). Pivot around that square's center, sample only from inside the square, and
gate the effect with the square itself (soft edges), NOT with the person mask: the mask is
the body silhouette and would clip the moved head to whatever used to be there.

ALWAYS emit a `// @detect-note:` line when you make such a substitution, stating what
the user asked for and what you targeted instead. It is not parsed — it exists so the
simplification is visible later in the shader history instead of looking like a bug.

Rules for @detect-coco:
- EXACTLY ONE entry per @detect-classes phrase, in the SAME ORDER. Different lengths
  make the whole line unusable, so count them before you write it.
- A phrase with no reasonable COCO class gets `-`. Do NOT drop the entry and do NOT
  drop the line: `-` is the correct, expected answer for "guitar", "dragon",
  "logo", "shadow". That slot simply finds nothing on the fast detector, which is fine.
- Otherwise pick the closest COCO class even when it is coarser: "television screen"
  -> `tv`, "red coffee mug" -> `cup`, "office chair" -> `chair`, "sofa" -> `couch`.
- NEVER let two slots use the SAME COCO class. A detection can only carry one slot, so
  the second would silently stay empty. If two of your phrases would need the same COCO
  class, MERGE THEM INTO ONE @detect-classes slot instead — e.g. do not write
  "television screen, computer monitor" (both `tv`); write one slot "screen" -> `tv`.
- Only these 80 names are valid, spelled exactly like this:
  person, bicycle, car, motorcycle, airplane, bus, train, truck, boat, traffic light,
  fire hydrant, stop sign, parking meter, bench, bird, cat, dog, horse, sheep, cow,
  elephant, bear, zebra, giraffe, backpack, umbrella, handbag, tie, suitcase, frisbee,
  skis, snowboard, sports ball, kite, baseball bat, baseball glove, skateboard,
  surfboard, tennis racket, bottle, wine glass, cup, fork, knife, spoon, bowl, banana,
  apple, sandwich, orange, broccoli, carrot, hot dog, pizza, donut, cake, chair, couch,
  potted plant, bed, dining table, toilet, tv, laptop, mouse, remote, keyboard,
  cell phone, microwave, oven, toaster, sink, refrigerator, book, clock, vase,
  scissors, teddy bear, hair drier, toothbrush

1. HARDWARE MEMORY ALIGNMENT CONTRACT (std430 standard):
To interface with the host CPU without causing memory misalignment corruption crashes, the 'Detection' layout block MUST map identically to this 4-byte padding architecture. Do NOT use float2 or float3 internally:
```hlsl
struct Detection {
    float4 boundingBox; // xy = pre-projected viewport center, zw = size in viewport space [0,1]
    float confidence;   // 0.0 to 1.0 accuracy score
    int labelID;        // SLOT INDEX into the @detect-classes list (0 = first phrase)
    float3 worldPosition; // Reference coordinates
    float depth;        // Distance scalar
    int hasDepth;       // boolean flag: 1=3D valid, 0=2D only
    int hasMask;        // boolean flag: 1=segmentation mask allocated, 0=none
    int maskIndex;      // Index positional step inside the layout grid atlas
    float padding;      // MANDATORY: Explicit 4-byte float structural padding for GPU alignment
};
```

2. HARDWARE UNIFORM & BUFFER DECLARATIONS:
You MUST explicitly declare all global uniform components when using computer vision features:

```hlsl
StructuredBuffer<Detection> _Detections;
int _DetectionCount;
int _HasMask;
int _MaskCount;
int _MaxMasks;
sampler2D _MaskTex;
```

3. MASK ATLAS SPACE-MAPPING FORMULA:
To execute a mobile-safe texture lookup sequence without compilation drops, you MUST implement this combined IF control flow paradigm:

- Always check 'if (_DetectionCount > 0)' before starting structural loop blocks.
- Filter out non-target slots instantly using a single continue check. TARGET is the
  zero-based slot index from your @detect-classes list: 'if (det.labelID != TARGET) continue;'
  (e.g. TARGET = 0 for the first declared phrase, 1 for the second, ...).
- Wrap all boundary logic calculations and coordinates inside a single integrated condition block:

```hlsl
float2 center = det.boundingBox.xy;
float2 size = det.boundingBox.zw;
float2 delta = abs(i.uv - center);

if (det.confidence >= 0.3 && size.x > 0.0 && size.y > 0.0 &&
    center.x >= 0.0 && center.x <= 1.0 && center.y >= 0.0 && center.y <= 1.0 &&
    delta.x < size.x * 0.5 && delta.y < size.y * 0.5) {

    float mask = 1.0;
    if (_HasMask == 1 && det.hasMask == 1 && det.maskIndex >= 0) {
        float2 localUV = saturate((i.uv - center) / size + 0.5);
        int gridX = det.maskIndex % _MaxMasks;
        int gridY = det.maskIndex / _MaxMasks;
        float cellSize = 1.0 / (float)_MaxMasks;
        float pad = 0.01;

        float2 paddedLocalUV = lerp(float2(pad, pad), float2(1.0 - pad, 1.0 - pad), localUV);
        float2 atlasUV = float2((float)gridX, (float)gridY) * cellSize + paddedLocalUV * cellSize;

        // MANDATORY edge anti-aliasing: the mask atlas is a low-resolution binary
        // coverage map. Sampling it raw gives hard, pixelated/stair-stepped edges.
        // Convert it into a resolution-independent soft edge with smoothstep over the
        // mask's own screen-space gradient (fwidth) so the outline stays smooth at any
        // object size. This is essentially free on the GPU. Use this 'mask' as the
        // coverage weight (e.g. lerp/alpha), NOT a hard 'if (mask > 0.5)' cutoff.
        float raw = tex2D(_MaskTex, atlasUV).r;
        float aa = fwidth(raw) + 1e-4;
        mask = smoothstep(0.5 - aa, 0.5 + aa, raw);
    }
    // Apply visual effects using 'mask' as a soft coverage weight (0..1) here.
}
```hlsl

4. MULTI-CLASS SHADERS:
When the user wants different effects per object type, branch on the slot index.
Example for `// @detect-classes: person, dog`:
    if (det.labelID == 0) { /* effect for person */ }
    else if (det.labelID == 1) { /* effect for dog */ }
The detector tags each detection with the slot index of the phrase it matched, so
these comparisons map 1:1 to your declared list — with no dependency on any fixed
label dataset.
